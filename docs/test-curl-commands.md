For local testing without real public DNS records, you can use `curl` to dynamically override the Host header and force the requests to hit your provisioned static Load Balancer IP (`8.233.55.181`).

### Test 1: Verify HTTP to HTTPS Redirect
Our `FrontendConfig` is configured to force HTTP traffic to HTTPS via a permanent redirect (301 status).

```bash
curl -I -H "Host: app.example.com" http://8.233.55.181/
```
**Expected Output:** 
You should see an empty body with `HTTP/1.1 301 Moved Permanently` and a `Location: https://app.example.com/` response header.

### Test 2: Verify Webapp-A Routing (Default Path)
To test HTTPS, we must use `-k` to ignore the certificate warnings since the Google Managed cert cannot finish provisioning until real DNS exists for `app.example.com`.

```bash
curl -k -H "Host: app.example.com" https://8.233.55.181/
```
**Expected Output:** 
You should see the standard "Hello, world!" HTTP response output from the `webapp-a` containers.

### Test 3: Verify Webapp-A Routing (Explicit Path)
```bash
curl -k -H "Host: app.example.com" https://8.233.55.181/a
```
**Expected Output:** 
Same standard output from `webapp-a`.

### Test 4: Verify Webapp-A Routing (Direct to Pod via Port Forward)
If your load balancer isn't provisioned yet, you can test app A natively by port-forwarding to your local machine.

```bash
# In Terminal 1: Run port block
kubectl port-forward svc/webapp-a 8081:80

# In Terminal 2: Run test
curl http://localhost:8081/
```
**Output:** 
```text
Hello, world!
Version: 1.0.0
Hostname: webapp-a-798c84c9f8-7dzmh
```

### Test 4b: Generate Traffic for Grafana Panels
Run a few requests against app A so the nginx proxy emits `request_time` logs and BigQuery/Grafana has data to plot.

```bash
for i in {1..20}; do curl -k -H "Host: app.example.com" https://8.233.55.181/a >/dev/null; done
```

If you want to generate local traffic instead of ingress traffic, keep the port-forward running and loop against localhost:

```bash
for i in {1..20}; do curl http://localhost:8081/ >/dev/null; done
```

After either command, wait a minute or two for Cloud Logging to export the new stdout rows into BigQuery, then refresh Grafana.

### Test 5: Verify Cloud Armor WAF Controls (SQL Injection)
The Ingress is protected by a Cloud Armor active WAF security policy via a `BackendConfig`. You can test it by forcing an OWASP-flagged payload.

```bash
curl -k -H "Host: app.example.com" "https://8.233.55.181/?id=1%20OR%201=1"
```
**Expected Output:** 
You should receive an `HTTP/2 403 Forbidden` response natively generated by the Cloud Armor edge, preventing the malicious payload from ever reaching your GKE Pods.
